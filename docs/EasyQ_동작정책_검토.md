## 1. 평소에도 터질 수 있음

### L7. 강의실 공유 IP에서 입장 전원 차단

- **설계:** "입장 코드는 없는 코드 · 폐기된 코드로 실패한 요청이 같은 IP에서 15분 20회를 넘으면 그 IP의 입장 코드 확인 · 입장을 15분 동안 거부"(7.1.2).
- **현재 구현:** v0.3 `backend/easyq_backend/participation.py`가 이 값(20회 / 900초)으로 동작한다.
- **현상:** 학교 와이파이는 강의실 전체, 때로는 건물 전체가 공인 IP 하나를 쓴다. 청중 50명 중 몇 명만 오타를 내거나, 강연자가 QR을 재발급한 뒤 옛 QR로 들어와도(폐기된 코드도 실패로 셈) 20회를 넘는다.
- **영향:** 그 IP의 **모든 청중이 15분 동안 입장할 수 없다.** 입장이 몰리는 강연 시작 직후에 일어나 체감이 크다.
- **제안:** IP 한도를 15분 100회로 올린다. 로그인 실패 · 코드 확인의 IP 한도(15분 100회)와 같은 수준이다. 5자리 코드(32⁵ ≈ 3,300만 조합)라 100회로도 무작위 대입은 막힌다.
- **변경 범위:** 7.1.2 · 6.2.4 · 8.2.6의 숫자, 구현 상수 하나. 프론트 변경 없음.

## 2. 특정 상황에서 데이터 · 개인정보 문제

### H6. 탈퇴 후 개인 질문 원문이 남음

- **설계:** 탈퇴 시 "회원 개인 기록과 미병합 라벨 후보를 지운다"(6.2.11-5). 순서는 정하지 않았다.
- **현상:** 스키마상 `participants.user_id`는 회원 삭제 때 CASCADE이고, `questions.participant_id`는 `SET NULL`이다. 개인 질문을 먼저 지우지 않고 회원 행을 지우면, AI 답변을 받은 **개인 질문과 답변 원문이 작성자 없는 행으로 남는다.**
- **영향:** 서비스는 정상 동작하지만 보관 정책(8.2.37)과 동의 화면의 약속을 어긴다.
- **제안:** 탈퇴 작업 순서를 명시한다. 접근 차단 → 미병합 후보 → 개인 질문 · 답변 · 필기 · 공감 · 평가 · 문의 → 공개 질문의 작성자 연결 해제 → 참가 행 → 회원 행.
- **함께 볼 것:** ADMIN 계정의 탈퇴 처리(검수 · 배포 이력 FK). `EasyQ_DB스키마_검토.md` 5번.

### M3. 종료 정리와 늦게 끝난 답변 작업의 경합

- **설계:** 종료 정리가 "시간 안에 끝나지 않은 질문은 이관한다"(6.2.9-2). 결과는 "점유 표식이 일치할 때만 저장"(6.1.2).
- **현상:** 종료 정리는 질문 작업의 점유를 빼앗지 않는다. 그래서 질문 작업은 점유 표식이 여전히 유효하고, 종료 정리가 ESCALATED로 바꾼 질문을 늦게 끝난 답변이 AI_ANSWERED로 덮어쓸 수 있다.
- **영향:** 종료 순간에 처리 중이던 질문에서만 드물게 생긴다. 강연 통계(종료 때 한 번 집계)와 질문 상태가 어긋난다.
- **제안:** 종료 정리가 이관할 때 해당 QA 작업을 CANCELLED로 바꾸고 점유 표식을 교체한다. 점유를 잃은 작업은 재시도하지 않고 끝낸다.

### M12. 평가용 강의 검사 대기 중 생긴 라벨 후보 누락

- **설계:** 목록을 받지 못했거나 검색 설정 버전이 맞지 않으면 "검사가 끝날 때까지 그 강연의 후보 생성을 미룬다"(6.1.6-5).
- **현상:** 후보가 생기는 계기(자동 이관 · 2차 근거 부족 · 철회 · 청중 평가)는 이미 지나간 뒤다. 검사가 끝난 다음에 후보를 만드는 단계가 없다.
- **영향:** 그 강연의 후보가 **조용히 빠진다.** 서비스는 정상으로 보이고, 재학습용 데이터만 줄어든다.
- **제안:** 검사가 끝나면 같은 교안 처리 작업이 그 강연의 사건을 다시 훑어 후보를 만든다. 같은 사건은 `event_key`로 한 번만 만든다.

### H8. 게스트 재시도 · 재입장 때 참가자 중복

- **설계:** "다시 요청하면 같은 참가자를 재사용해 참가자가 중복되지 않는다"(API-19). 그런데 API-19에는 게스트를 식별할 입력이 없다.
- **현재 구현:** v0.3은 auth가 실패했을 때(503)만 서명한 `easyq_join_retry` 쿠키(10분)를 준다. 그래서 auth 장애 중 재시도는 대부분 막힌다.
- **남은 현상:** 게스트 세션 쿠키를 잃고 다시 들어오면 새 참가자가 된다. 정원은 활성 참가자 수로 세므로, 이전 참가가 정원 50명을 계속 차지한다.
- **제안:** 프론트를 바꾸지 않아도 되는 방식이다.
  - 입장 확인 쿠키를 새 게스트 참가마다 준다(유효 시간은 게스트 인증과 같은 24시간).
  - 정원은 회원과, 세션이 유효하거나 입장 후 10분 이내인 게스트만 센다.

### H11. 강연 중 원자료 즉시 파기

- **설계:** API-40 SESSION("HOST가 강연 원자료를 즉시 지운다")에 강연 상태 제한이 없다. 반면 교안 삭제(API-24)는 "강연 중 근거 보호"를 이유로 DRAFT · ENDED에서만 받는다.
- **영향:** 강연 중에 누르면 근거 조각이 사라져 진행 중인 판정이 모두 이관된다. 화면은 지난 강연에만 삭제 버튼을 두므로 일어날 가능성은 낮다.
- **제안:** SESSION 삭제는 LIVE에서 409 `SESSION_STATE_CONFLICT`로 거부한다. DRAFT 삭제를 받을지도 함께 정한다.
