# EasyQ AI팀 협업 규칙 (백엔드용)

AI팀(엄윤종 · 최의찬)에서 받은 개발 규칙과, AI 레포 · 학습서버와 맞물리는 작업을 할 때 지켜야 할 내용을 모은 문서다.
교안 처리 · 발화 색인 · 검색 · 판정 · 학습서버 연동을 개발할 때 이 문서를 먼저 확인한다.

- 받은 날: 2026-11-24 (교안 청킹 질문 4개에 대한 AI팀 답변)
- 이 문서와 설계서가 다르면 설계서를 따르지 않고 **AI팀과 먼저 맞춘다.** 아래 규칙은 설계서에 수치가 없던 부분을 AI팀이 확정한 것이다.

## 1. 교안 처리 규칙 (확정)

서비스와 학습서버는 **같은 PDF 추출 도구와 같은 정리 규칙**을 써야 한다. 다르게 추출하면 깨진 부분이 다르게 나와서, 같은 교안인데도 평가용 강의 판정(6.1.6)에서 다른 강의로 볼 수 있다.

### 1.1 처리 순서

1. 텍스트 추출
2. 저작권 줄 삭제
3. 깨진 줄 삭제
4. 내용 적은 쪽 판정
5. 청킹

### 1.2 PDF 추출

- PyMuPDF `page.get_text("blocks", sort=True)`를 쓴다.
- 결과 중 **글 블록만** 쓴다(이미지 블록은 버린다).
- 블록 하나를 문단 하나로 본다. 블록 안의 줄은 공백으로 이어 붙인다.
- 설계서 10.1 기술 스택(PyMuPDF · python-pptx)과 같다.

### 1.3 PPTX

- 슬라이드 본문만 추출한다. **발표자 노트는 넣지 않는다.**
- 이유: F2-2는 교안 텍스트 기준이고, 근거 조회 API로 청중에게 인용 구절이 보이므로 비공개 메모가 노출될 수 있다. PDF와 학습 데이터(MIT OCW PDF)에도 노트가 없다.

### 1.4 저작권 줄 삭제

- 6.172 슬라이드 거의 모든 쪽에 있는 `© 2008–2018 by the MIT 6.172 Lecturers` 같은 저작권 문구 줄을 지운다.

### 1.5 깨진 줄 삭제

일부 PDF(6.172)는 글꼴 때문에 `!"##$* %&'`처럼 깨진 글자로 추출된다. **줄 단위로** 판정해서 다음 중 하나면 그 줄을 지운다.

- 아래 글자를 뺀 나머지 중 글자 · 숫자 비율이 **0.5 미만**
  - 빼는 글자: 괄호 `( ) [ ] { }` 전부, `=`, `'`, `"`, `,`, `:`
- 단어처럼 보이는 토큰이 **절반 미만**

`x = a[i]`, `L = ['a','b','c']` 같은 코드 줄은 남아야 한다.

### 1.6 내용 적은 쪽 제외

- 판정 기준: 정규화 후 **20자 미만**이거나 **내용어 3개 미만**인 쪽
- 내용어 수 = Kiwi 명사(`NNG`, `NNP`) 수 + 정규식 `[A-Za-z][A-Za-z0-9]+`에 맞는 영단어 수
  - `x`, `n` 같은 한 글자 변수는 세지 않는다.
- 제외한 쪽은 `page_count`에는 넣고 `chunk_count`에서만 뺀다.
- 다음 쪽과 합치지 않는다. 인용 위치 "교안 p.N"의 페이지 번호를 지키기 위해서다.

### 1.7 청킹

- 조각 최대 **400토큰**, 토크나이저는 `BAAI/bge-reranker-v2-m3`(XLM-RoBERTa SentencePiece)
- 한 쪽을 여러 조각으로 나눌 때만 약 **50토큰 겹침**. 쪽 사이에는 겹치지 않는다.
- 근거: 판정 모델 입력은 질문 + 근거 합쳐 512토큰(설계서 표 4.3).
  - AI팀이 실제 토크나이저로 잰 결과, 400토큰 조각에 질문은 108토큰(한국어 약 195자)까지 들어간다.
  - 질문이 최대 200자이면 513토큰으로 1토큰 넘친다. 설계서 4.3대로 근거 뒷부분을 잘라서 처리한다.

## 2. 발화 조각

- **약 30초 단위**로 묶어 색인한다(F3-3, 6.2.5). 발화부터 검색 가능(READY)까지 45초 이내가 목표다.
- 확정된 발화 경계에서 끊으므로 정확히 30초가 아니라 "약 30초"다.
- 일시정지하거나 종료할 때 남은 발화도 조각으로 저장한다.
- 발화 조각 사이 겹침은 설계서에 없다. 필요하면 AI팀과 정한다.

## 3. 판정 모델 · 임베딩 · 검색 (설계서 기준 요약)

| 항목 | 값 | 근거 |
|---|---|---|
| 판정 모델 | `BAAI/bge-reranker-v2-m3` 파인튜닝, fp16 | 4.2 · 4.3 |
| 판정 입력 최대 길이 | 512토큰(질문 + 근거), 넘치면 근거 뒷부분을 자름 | 표 4.3 |
| 임베딩 | Gemini Embedding 2, 768차원 | 6.1.5 |
| 키워드 색인 | Kiwi + PostgreSQL `tsvector`(simple) | 6.1.5 |
| 검색 결합 | 벡터 20 + 키워드 20을 RRF로 합쳐 상위 20, 같은 강연 안에서만 | 6.1.5 |
| 검색 설정 버전 | `retrieval_config_version`(rc-vN): 청킹 규칙 · 임베딩 모델과 차원 · Kiwi 버전 · 결합 방식 · 후보 수 · 코드 버전 | 6.1.5 |
| 평가용 강의 판정 | 5단어 묶음, 조각 겹침 80% 이상인 조각이 30% 이상이면 평가용 강의 | 6.1.6 |

청킹이나 정리 규칙이 바뀌면 검색 설정 버전이 바뀐다. 이미 색인한 조각과 학습 데이터의 기준이 함께 바뀌므로, 버전은 혼자 올리지 않는다.

## 4. 협업 경계

### 4.1 레포와 코드 위치

- **공용 검색 모듈 `retrieval`은 AI 레포에 있다**(https://github.com/EasyQ-P/AI). 이 레포에 복사하거나 다시 만들지 않는다.
- 태그로 고정해 설치한다.
  ```
  uv add "retrieval @ git+https://github.com/EasyQ-P/AI@vX.Y.Z#subdirectory=retrieval"
  ```
- 청킹 · 추출 · 정리 규칙 · 키워드 색인 · RRF 검색 · 겹침 계산 · 검색 설정 버전을 바꿔야 하면 AI 레포에 요청하고(최의찬), 새 태그가 나오면 이쪽 버전을 올린다.
- worker의 R2~R4(STT 중계 · 발화 색인 · 검색 · 판정 · 답변) 서비스 코드는 이 레포에서 작업한다.

### 4.2 바꾸지 않는 계약

아래는 설계서대로 맞추고 이쪽에서 바꾸지 않는다. 바꿔야 하면 먼저 해당 담당자와 합의한다.

| 계약 | 설계서 | 맞추는 사람 |
|---|---|---|
| 학습서버 API | 7.4 | 최의찬 · 엄윤종 |
| WebSocket 이벤트 | 7.3.10 | 심주혜 |
| 공통 응답 객체 | 7.3.1 | 심주혜 |

### 4.3 리뷰

- R2~R4 · L 연계(학습서버 어댑터 · 동기화)와 학습서버 API 계약을 건드리는 PR은 **최의찬을 리뷰어로 넣는다.**
- 응답 객체 · WebSocket 이벤트를 바꾸는 PR은 심주혜에게 알린다.

### 4.4 학습서버 연동

- 학습서버는 정해진 API만 부르는 어댑터로 호출한다. 임의 URL · 명령 · 파일 경로를 입력받지 않는다.
- 주소는 `TRAINING_API_BASE_URL`(Docker bridge 호스트:9000 SSH 터널)이다.
- `X-API-Key`는 backend · worker만 갖고, 로그에 남기지 않는다.
- 판정 추론(7.4.26)이 800 ms를 넘기거나 오류이면 **그 질문만** LLM_ONLY로 판정한다.

### 4.5 학습서버 쪽 준비 일정 (진도표 v6)

| 태그 | 학습서버에서 준비되는 것 | 서비스 쪽 작업 |
|---|---|---|
| v0.4 (12/3) | 판정 추론(7.4.26), 서버 상태 확인(7.4.1) | 하이브리드 검색 · LLM_ONLY 경로 |
| v0.5 (12/4) | 판정 추론 연결 | 판정 모델 판정, `decision_snapshot` 기록 |

## 5. 현재 프로토타입(`backend/easyq/`)에서 바꿀 것

| 위치 | 지금 | 바꿀 내용 |
|---|---|---|
| `retrieval.extract_pages` | pypdf `extract_text`, `strict=True` | PyMuPDF 글 블록 추출(1.2) |
| `retrieval.chunks` | 800자 · 100자 겹침, 쪽마다 독립 | 400토큰 · 쪽 안에서만 50토큰 겹침(1.7) |
| 정리 규칙 | 없음 | 저작권 줄 → 깨진 줄 → 내용 적은 쪽 판정(1.4~1.6) |
| PPTX | 슬라이드 본문만 | 그대로 유지(노트 제외) |
| `retrieval.py` 자체 | 이 레포에 직접 구현 | AI 레포 `retrieval` 패키지를 태그로 설치해 호출(4.1) |
| `Settings.retrieval_version` | `easyq-v0.3-768-c800-o100` | AI팀이 정한 rc-vN 사용 |

## 6. AI팀에 확인할 것

- 추출 · 저작권 줄 · 깨진 줄 · 내용 적은 쪽 판정 함수가 `retrieval` 패키지에 들어가는지. 들어가면 서비스는 그 함수를 그대로 부르고, 규칙을 다시 구현하지 않는다.
- 저작권 줄 판정 패턴: 6.172 문구에만 맞추는지, `©` · `Copyright`로 시작하는 줄 전반인지.
- "단어처럼 보이는 토큰"의 정확한 정의.
- "정규화 후 20자"의 정규화 방식(평가용 강의 판정의 NFKC · 소문자 · 문장부호 공백 처리와 같은지).
- 이 규칙을 반영한 `retrieval` 첫 태그 번호와 검색 설정 버전(rc-vN).
