# 설계서 v1.4 작업본 검토 결과 (2026-11-27)

> 대상: `CodingAnt팀_설계서_v1.0_백엔드v1.4작업본.hwpx`, `easyq_schema_v1.4.sql`, `easyq_grants_v1.4.sql`
> 방법: hwpx 본문을 텍스트로 뽑아 영역 5개(DB / 서비스 API / 학습서버 · AI 연동 / 프론트 연동 / 프로세스 · 정책)로 나눠 정독 · 대조했다. 고친 것은 없다.
> 줄 번호(L…)는 추출 텍스트 기준이라 한글 문서 쪽수와 다르다. 찾을 때는 절 번호 · API 번호를 쓴다.
> 표시: **[대조]** = 종합 단계에서 원문을 한 번 더 직접 확인한 것. 표시 없는 것은 영역 검토에서 원문 인용으로 확인된 것. **[추정]** = 원문은 맞지만 영향이 구현 방식에 달린 것.
> 제외: `AI팀_요청사항.md` A1~A6, `프론트팀_요청사항.md` N1 · N2 · S1~S5 · Q2 · Q3, `재생성 필요 그림.md`에 이미 있는 것.

## 0. 요약

- **DDL은 그대로 적용된다.** 적용이 실패하는 구문 · 순서 문제는 찾지 못했다(실행은 하지 않은 정적 검토).
- v1.2 검토에서 고친 항목(H3 · H4 · H5 · H7 · H8 · H9 · H11 · M2 · M3 · M5 · M7 · M13 · L3 · L4 · L7 · L9)은 본문 · DDL · 권한에 일관되게 들어 있다.
- 남은 문제는 높음 26건, 중간 약 50건, 낮음 약 30건이다. 높음은 아래 1절에 모았다.
- 수치(90일, 12시간/24시간, 정원 50, 후보 20, 800 ms, 768차원, 입력 길이)와 상태값 enum, API 65개의 번호 · 경로 · 메서드, 오류 코드의 HTTP 상태는 문서 전체에서 일치한다.

### 2.1 DB 스키마 · 권한

- **D-5 [대조]** `summary_notes.source_refs`: 본문은 "기본 []", DDL은 DEFAULT 없는 NOT NULL. FINALIZE가 값을 생략하면 실패한다.

- **D-7** `ws_events` "번호 이후 재조회"는 늦게 커밋된 작은 번호를 놓친다(IDENTITY 번호는 커밋 순서와 다르다). 겹침 구간 + 중복 제거 규칙이 필요하다. [추정]

- **D-10** `training_runs` 갱신 주체: 7.4.8 "backend가 갱신" ↔ 8.2.24 "worker가 주기 조회" ↔ 권한(backend는 UPDATE 없음).
- **D-11** 8.2.6 "backend DB 계정은 JOIN_CODE 범위 행만 읽고 쓴다"는 DB 권한으로 보장되지 않는다(`bucket_key`가 해시). 본문을 "코드 규칙"으로 낮춰야 한다.

## 4. 대조했는데 문제없던 영역

- API 65개: 7.2 목록과 7.3 상세의 번호 · 메서드 · 경로가 모두 같다(GET 23 + POST 23 + PUT 7 + PATCH 6 + DELETE 6). 7.1.4의 auth 분기는 API-01~10과 정확히 맞는다.
- 7.3에 나온 `error.code`는 모두 8.4.2에 있고 HTTP 상태도 같다. 8.4.3의 6xx ↔ 서비스 코드 대응도 맞다.
- 33개 테이블의 컬럼 이름 · 타입 · 길이 · NULL · PK가 위 항목 외에는 DDL과 같다. 상태값은 모두 VARCHAR 길이 안이고, 복합 FK가 참조하는 UNIQUE는 FK보다 먼저 만들어진다.
- `consents` CHECK 4개와 `auth_session_view`의 열은 7.1.1 · 7.1.3과 맞다. worker의 컬럼 단위 권한은 검증값을 뺀다.
- 탈퇴 · 90일 파기의 삭제 순서는 FK 동작과 충돌하지 않는다(MEMBER 계정 기준).
- 개인 답변 격리: `answer.*` · `question.progress`는 질문자(검토용은 HOST)에게만 가고 새는 경로를 찾지 못했다.
- 학습서버 API 28개의 경로 · T-번호 · 대응표(7.4.30)가 서로 일치한다(keepalive는 A1).
- 평가용 강의 겹침 규칙(5단어 묶음 · 80% · 30%)과 병합 시 익명 처리가 3.3.4 · 6.1.6 · 6.4.3 · 7.4.28에서 같다.
